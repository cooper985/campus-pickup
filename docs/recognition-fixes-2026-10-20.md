# 识别等待与地点关联修复（2026-10-20）

## 根因与证据边界

真实代码链路：选择本地图片 → 读取 base64 → 超过 512 KiB 时压缩并重读 → 作为 callFunction 参数发送 → 云函数身份/图片校验 → 腾讯云 GeneralBasicOCR → 返回文字与坐标 → 前端解析 → 更新草稿 → 用户确认才写本地存储。

没有独立的云存储上传。cloud_roundtrip 含请求传输、平台排队/冷启动、函数执行和响应传输，不能将它直接称为上传耗时。原代码已有云调用 20 秒配置、服务端 OCR 12 秒兜底和 SDK 10 秒配置，但前端没有包含文件读取与压缩的整体等待期限，也没有跳过入口；未知异常丢失类型，无法定位历史真机等待。原解析器无取件码会正常返回空数组，不能据此断言“无取件码导致 OCR 服务器失败”。那次请求的真实耗时瓶颈尚需新日志复测。

地点误判可从旧算法直接解释：它把取件码之前含三个以上汉字的普通行收集为候选，再拼接前两项；“物流求助”“收…市”未被排除。旧云函数仅返回文字，丢弃 ItemPolygon 坐标。

## 改动

- recognition-task.js 的 WAIT_TIMEOUT_MS = 15000 是单图前端测试上限，覆盖本地准备及云请求。测试可通过页面 recognitionTimeoutMs 覆盖。JS 定时器受事件循环/后台挂起影响，不是硬实时保证。
- 跳过当前图片继续下一图；取消本批停止后续启动。取消/超时只停止等待，不声称终止云端 OCR。已发出的调用仍可能占用 OCR 次数，手动重试也是一次新请求。
- 单图失败、无取件码、超时不阻塞后续图片。成功草稿保留，失败图支持独立手动重试；不自动重试。迟到成功或拒绝均被消费且不更新页面。卸载后不再写旧页面状态。
- 已找到码、到站无可用码、运输上下文无取件码、未知状态无取件码、调用失败、主动取消、前端超时分开表示。“可能未显示或隐藏”是推测，不断言隐藏原因。
- 优先明确取件地址/派送至语义，用 OCR 行框的重叠、距离和邻近包裹判断关联；无坐标时保守使用文字顺序。剔除按钮、城市、运输节点及显式地图文本。无充分语义或有冲突时使用原有“待确认地点”。不拼接含糊候选，仍可手动编辑。
- 云函数增加可选 boxes 与 timings.ocrMs；旧前端可忽略新增字段，新前端也兼容旧云函数缺少坐标的返回。
- 本地持久化结构、存储服务、重复导入服务及核销方法未修改；没有迁移。

## 日志及真机定位方法

日志前缀 `[pickup-timing]`，只包含阶段、毫秒和白名单错误类型，不输出文件路径、图片、OCR 原文、OPENID、供应商异常详情或密钥。OCR 原文仍仅在当前页面供用户核对，不作为诊断日志或持久化数据。

| 阶段 | 含义 |
| --- | --- |
| image_read / image_compress / compressed_read | 首次读取 / 压缩 / 压缩后读取 |
| image_prepare | 图片准备成功的合计 |
| cloud_roundtrip | 云调用整体往返；超时/取消也记录当前阶段等待耗时 |
| tencent_ocr（云函数日志） | 腾讯 OCR 调用或服务端兜底超时耗时 |
| text_parse | 地点、取件码及重复检测元数据解析 |
| page_update | setData 到渲染回调的耗时 |
| image_total | 单图等待结束及处理耗时，不包括渲染回调 |

失败码示例：NETWORK_FAILED、CLOUD_FAILED、TIMEOUT（服务端 OCR 超时）、OCR_FAILED、WAIT_TIMEOUT（前端等待上限）、CANCELLED。网络与函数调用失败只能依据微信返回的错误类型/消息区分；未明确给出网络信息时归类 CLOUD_FAILED，不猜测原因。读图/压缩有各自错误码。

复测时先检查当前阶段是否超时；云往返慢则对照云函数 OCR 日志。云往返减去 OCR 时间只是传输、平台调度和其他函数开销的合计，不能精确归因于网络上传。旧部署没有新增服务端日志时仍不能做这一步拆分。

## 需要重新进行的真机验收

1. 单独导入运输中/预计后天送达截图：OCR 成功时显示合法无取件码结果；网络慢时约 15 秒结束等待并可重试。
2. 导入问题原截图：核对 603402 和一中看台；OCR 不完整/关联不可靠时应标待确认而非按钮或城市。手动修改仍可保存。
3. 已到站但取件码未显示的截图：提示到站但无可用码，不报服务器错误。
4. 三张混合导入（两张有取件码，一张无取件码/失败）；主动跳过一张；取消整批；成功草稿保留。超时后重试并等待旧请求返回，界面不能变回旧状态。
5. 再做原四项：确认导入、退出重启恢复、一键核销、重复截图导入。保留原有待取/已取记录。
6. 在 Wi-Fi 与移动网络各记录上述脱敏阶段耗时，再决定是否调整 15 秒阈值。不要为测试反复自动重试。
