# 本地记录保存与基础去重

完成日期：2026-10-20（Asia/Shanghai）。仅修改当前微信小程序；没有云端部署、付费 OCR 调用或权限变更。

## 使用流程

识别结果先进入待确认列表，可沿用“修改”核对地点和取件码。点击“确认导入”后，检查与已保存记录以及本批已接受记录的重复关系，最后一次性保存。选图、再次识别、单图失败均不清空已保存看板。取消确认不写入；疑似重复可跳过或确认新增；相同可靠运单提示跳过，也可取消整批导入。

标记已取、恢复待取、修改已保存记录均立即同步保存，写入并回读校验成功后才更新看板。页面 onLoad 自动恢复待取及已取记录。

## 数据与保护

- 主键：`campus-pickup.records`；备份键：`campus-pickup.records.backup`。
- 外层结构：`{ version: 1, savedAt: 毫秒时间戳, records: [...] }`。
- 每条记录仅保存：`id`、`station`、`code`、`carrier`、`waybillNumber`、`taken`、`createdAt`、`updatedAt`、`takenAt`。
- `taken` 为状态；待取时 `takenAt` 为 null，标记已取时赋取件时间，恢复待取时清空。编辑不改变 ID、创建时间或既有取件时间。
- ID 包含时间、递增序号和随机部分，生成时再检查与当前记录是否冲突。
- 每次覆盖主键前先保存并校验上一版有效快照，主键写入后再次回读校验。旧页面发现存储内容已改变时拒绝覆盖。
- 只在两个键确实不存在时视为首次使用。格式错误、字段异常、重复 ID、未知版本或读取失败均进入只读保护；有有效备份则显示上一版，同时提示其可能不是最新。没有自动清空、删除或重置逻辑。
- 写入失败或结果不确定时暂停后续写入，保留上次看板及本次草稿，提示重启核对。可能存在“实际已写入、API 随后报错”的情形，因此不擅自回滚覆盖；重启重新读盘。
- 原始损坏值保持原样。持续格式损坏需要后续人工恢复；重启只能解决暂时性故障，不能修复错误数据。未来版本需要显式迁移，当前不会猜测未知版本格式。
- 字段白名单不保存图片路径、图片内容、OCR 原文或来源截图索引。草稿和原文只在当前页面内存保留，导入完成后清理。已有 OCR 服务、云函数和取件码解析核心未修改。

## 去重边界

1. 单包裹截图中，仅采纳“运单号 / 快递单号 / 物流单号”明确标注、格式合规且唯一的号码；相同号码优先判为重复，不新增，原记录不删除。
2. 两个明确且不同的运单号允许使用相同取件码。
3. 缺少可靠号码时，用规范化后的地点与取件码匹配，区分待取、已取状态；地点未知但取件码一致也提示确认。已取件取件码可能复用，不能自动拒绝新增。
4. 多包裹截图未新增版面关联算法，不强行把一个号码或快递公司分配给多个包裹，退回疑似重复确认。快递公司无法可靠确定时保存空字符串。
5. OCR 文字错识、地点改名、用户编辑过取件码等可能导致漏报；这不是图片指纹去重或完整物流身份校验。没有为了去重保存截图或完整原文。
